VS Code website / redesign evidence

A deeper read of Adobe CJA · Jul 23–Aug 21, 2026

What the homepage is really for.

The data points to three different audiences—not one download funnel.

The redesign opportunity: serve a new visitor, an existing user, and a tutorial referral differently.

01 · The new model

The homepage is doing three jobs at once.

72%

First impression

Most people are new to the tracked Microsoft web ecosystem.

74%

Utility hub

Most Microsoft-referrer views come from Home, Thank You, or Download.

13.7k

Ecosystem handoff

Distinct external URLs send people from AI, tools, tutorials, and classrooms.

One static page hierarchy cannot serve all three equally well. The site needs a clear default plus intentional alternate paths.

04 · Returning users

of Microsoft-referrer homepage views came from Home, Thank You, or Download.

Existing users use Home as a reset button.

What to do: when the referrer is Download or Thank You, show “Already installed?” actions: open VS Code, import settings, Extensions, Docs, Release Notes.

169,687 of 228,506 Microsoft-referrer page views came from code.visualstudio.com, /thank-you, or /download.

These are recorded actions, not unique people, and the Try free action opens a menu.

07 · Referred learners

13.7k

distinct external URLs referred homepage traffic.

The ecosystem is doing part of the onboarding.

After ChatGPT and Gemini, no single source produced more than 3% of external page views. The long tail includes GitHub, PlatformIO, Flutter docs, MDN, Udemy, Google Classroom, and many schools.

What to do: create a stable partner-friendly setup route: detect OS, explain three install steps, then return the person to their tutorial.

AI sent many external entries, but ChatGPT + Gemini produced 54.1% of external page views versus 58.8% of entries—slightly less repeat homepage activity than the external average.

08 · Proposed site architecture

Build one clear default and two fast exits.

01 / DEFAULT

New visitor

What VS Code is, core editor proof, correct Download, then choose a language or workload.

02 / UTILITY PATH

Existing user

Open Web or app, Docs, Release Notes, Extensions, and settings/import help.

03 / DEDICATED ROUTE

Referred learner

Fast setup, first-run instructions, and a return to the tutorial or tool that sent them.

Also fix the header: category names should lead somewhere. The dropdown arrow should be the dropdown.

09 · Success criteria beyond Download

Measure whether each audience finishes its job.

New visitors
Meaningful next steps per 1,000 New People

Download delivered, Open Web, workload selected, or a purposeful Docs path—reported separately instead of collapsed into raw clicks.

Navigation
Menu choice after menu open

Replace the current aggregate 14 / 33 / 18-per-100 diagnostic with a true sequenced completion rate.

Returning users
Useful exit without another Home loop

Open app, Docs, Updates, or Extensions after arriving from Download or Thank You.

Add section impressions and stable action IDs. Then measure clicks per impression, not the current text-derived Link Click total.
